# Тестовые диалоги Abramenko Studio

## booking
«Записаться» → «Женская стрижка» → «Филиал 1» → `15.09.2026` → `12:00` → имя → `+77001234567` → «нет» → «Да, отправить».

Если Telegram-уведомление не отправилось, заявка сохраняется и владелец может нажать «Повторить отправку». Чужой Telegram получает отказ, а параллельный повтор не дублирует отправку.

Ожидание: порядок полей строго соблюдается; сначала заявка сохраняется со статусом `pending_confirmation`, затем администратор получает карточку. Визит не объявляется подтверждённым.

## booking_date_validation
«Записаться» → услуга → филиал → `15.09` (без года) → `01.01.2020` (прошлая дата).

Ожидание: принимаются только полные даты `ДД.ММ.ГГГГ` в будущем; оба неверных ввода отклоняются с подсказкой «Введите корректную будущую дату: ДД.ММ.ГГГГ».

## coloring
«Записаться» → «Окрашивание» → филиал → дата → время → имя → телефон → мастер/«нет» → длина → желаемый результат → последнее окрашивание → готовность прислать фото → подтверждение.

Ожидание: ответы сохранены в нормализованном payload и карточке. Бот не ставит диагноз, не сообщает цену и не обещает результат.

## faq
Открыть «Цены», «Адреса» или «График».

Ожидание: бот сообщает, что данные не утверждены, и направляет к администратору. «Услуги и цены» показывает только подтверждённый список услуг.

## model_request
«Стать моделью» → имя → телефон → услуга → портфолио/«нет» → «Филиал 1» → подтверждение.

Ожидание: неверный телефон или филиал отклоняется. После подтверждения заявка сохраняется, затем отправляется карточка; дата и время — `—`.

## Ошибка уведомления
При пустом `ADMIN_CHAT_ID` или ошибке Telegram заявка остаётся в БД с `notification_status=failed` и текстом ошибки. Пользователь видит, что заявка сохранена, но уведомление не отправлено; бот не утверждает обратное.
